# gotree Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A k9s-style Bubble Tea TUI that lists every git repo (and its worktrees) in the start folder with its
git state. It does back-to-default+pull, pull, fetch and worktree removal in one key, and hands a chosen folder
back to the shell for `cd`.

**Architecture:** Single `package main` at the repo root. All git access goes through one `git()` helper that
shells out to the `git` CLI. Pure parsers turn git output into structs. Scan and action functions are plain Go
and are tested against real temp repos. The Bubble Tea model only orchestrates them through `tea.Cmd`s, fed by
an ordered worker pool.

**Tech Stack:** Go 1.27, `github.com/charmbracelet/bubbletea`, `github.com/charmbracelet/bubbles` (textinput),
`github.com/charmbracelet/lipgloss`, GoReleaser v2, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-06-gotree-design.md`. Read it fully before starting any task. Where
this plan is silent, the spec decides.

## Global Constraints

- Module path `github.com/yggdrion/gotree`. Binary name `gotree`.
- Shell out to `git` via `os/exec`. No Go git library.
- Every git call runs with env `GIT_TERMINAL_PROMPT=0` and `GCM_INTERACTIVE=never` (no credential prompts can hang a worker).
- Pull is always `git pull --ff-only`. Discard is `git reset --hard` then `git clean -fd` (never `-x`, never `-ff`).
- Never delete a branch. Never act without a key press, and never take a destructive action without a confirm.
- Default branch comes from `git symbolic-ref --short refs/remotes/origin/HEAD`. Never hardcode `main`.
- `CGO_ENABLED=0`. Use `path/filepath` everywhere. Normalize git-reported paths with `filepath.Clean(filepath.FromSlash(p))`.
- Targets: linux/windows/darwin × amd64/arm64.
- Concurrency limit for git work: 8 workers.
- Work order: newest-mtime-first (spec "Work order"). Display sort after load: `Status.Updated` desc.
- Workflows: emoji names, actions pinned to full commit SHA with a `# vX.Y.Z` comment, Homebrew secret `HOMEBREW_TAP_TOKEN`.
- Commits: Conventional Commits (`feat:`, `test:`, `ci:`, `docs:`).

## Review Focus

1. **Credential prompts.** A repo whose remote needs auth must fail its fetch with an error on that row. It must not hang the pool or pop a prompt. Pinned in Task 1 (`TestGitEnvNoPrompt`).
2. **Windows path forms.** `git worktree list` reports `C:/Users/...`, while `os.ReadDir` gives `C:\Users\...`. Dedupe and parent matching must treat them as equal. Pinned in Task 1 (`TestNormPath`) and Task 3 (`TestDedupeLinkedWorktree`).
3. **Empty or remote-less repo.** A freshly `git init`'d folder with no commits and no `origin` must load with `Default == ""`. It must not crash, and its row shows `?`. Pinned in Task 2 (`TestReadStatusEmptyRepo`).
4. **Stale worktree.** A worktree folder deleted by hand (git marks it `prunable`) must be skipped, not crash the load. Pinned in Task 3 (`TestLoadRepoSkipsMissingWorktree`).
5. **Paths with spaces and non-ASCII.** The cd file must hold exactly the UTF-8 path, with no BOM and no newline. Pinned in Task 7 (`TestWriteCDFile`).

### Task 1: Module, git runner, parsers

**Files:**
- Create: `go.mod`, `git.go`, `git_test.go`

**Interfaces:**
- Produces:
  - `func git(dir string, args ...string) (string, error)`: runs `git -C dir args...`. Returns stdout with trailing
    whitespace trimmed. On failure, the error text is `strings.TrimSpace(stderr)` (fall back to `err.Error()`).
  - `func gitEnv() []string`: `os.Environ()` plus `GIT_TERMINAL_PROMPT=0` and `GCM_INTERACTIVE=never`. `git()` uses it.
  - `func normPath(p string) string`: `filepath.Clean(filepath.FromSlash(p))`. On Windows it also lowercases
    the drive letter for comparison.
  - `type branchInfo struct { Head, OID, Upstream string; Detached, HasAB bool; Ahead, Behind int; Files []string }`
  - `func parseStatusV2(out string) branchInfo`: parses `git status --porcelain=v2 --branch` output.
    `# branch.oid`, `# branch.head` (`(detached)` sets Detached), `# branch.upstream`, `# branch.ab +A -B` (sets HasAB).
    Every non-`#` line is one changed file, and Files holds its path (last field; for `?` lines, everything after `? `).
    Upstream set but no `branch.ab` line means the upstream is gone.
  - `func parseDefaultBranch(symref string) string`: `"origin/beta7"` gives `"beta7"`, `""` gives `""`.
  - `type wtEntry struct { Path, Branch string; Bare, Prunable bool }`
  - `func parseWorktreeList(out string) []wtEntry`: parses `git worktree list --porcelain`. Blocks are separated by
    blank lines. Branch has `refs/heads/` stripped, and Path goes through `normPath`.

### Task 2: ReadStatus + temp-repo fixture

**Files:**
- Create: `status.go`, `status_test.go`, `helpers_test.go`

**Interfaces:**
- Consumes: `git`, `parseStatusV2`, `parseDefaultBranch` (Task 1).
- Produces:
  - ```go
    type Status struct {
        Branch   string    // "" when detached
        Detached bool
        SHA      string    // short (7) sha, used when Detached
        Upstream string    // "" = no upstream
        Gone     bool      // upstream configured but missing
        Ahead, Behind int
        Files    []string  // uncommitted, incl. untracked
        Default  string    // "" = unknown → UI shows "?"
        Merged   bool      // not on Default and HEAD is ancestor of origin/<Default>
        Updated  time.Time // max(last commit time, mtime of index)
        Err      string    // last load/action error, short
    }
    ```
  - `func ReadStatus(path string) Status`: never panics. It records git errors in `Err` and keeps the partial state.
    Calls: `status --porcelain=v2 --branch`, `symbolic-ref --short refs/remotes/origin/HEAD` (an error means Default ""),
    `merge-base --is-ancestor HEAD origin/<Default>` only if Default != "" and Branch != Default (exit 0 means Merged),
    `log -1 --format=%ct` (an error means zero time), and the index mtime via `rev-parse --path-format=absolute --git-path index`.
    A "no commits yet" repo must not set `Err`.
  - Test helpers in `helpers_test.go` (test-only, used by Tasks 2–4):
    - `func gitT(t *testing.T, dir string, args ...string) string`: runs git, `t.Fatal` on error.
    - `func newFixture(t *testing.T) (remote, clone string)`: creates `t.TempDir()`, a bare remote `git init --bare -b beta7`,
      a seed clone with one commit pushed to `beta7`, then `clone` = a fresh `git clone` of the remote (so
      `origin/HEAD` → `origin/beta7`). It sets `GIT_AUTHOR_NAME/EMAIL`, `GIT_COMMITTER_NAME/EMAIL` and
      `GIT_CONFIG_GLOBAL=<tempfile>` via `t.Setenv` so the user's own config never leaks in.

### Task 3: Scan: discovery, worktrees, dedupe, ordering

**Files:**
- Create: `scan.go`, `scan_test.go`

**Interfaces:**
- Consumes: `git`, `normPath`, `parseWorktreeList` (Task 1); `Status`, `ReadStatus`, `newFixture`, `gitT` (Task 2).
- Produces:
  - ```go
    type Repo struct {
        Path, Name string  // Name = folder base name
        CommonDir  string  // normPath(rev-parse --path-format=absolute --git-common-dir)
        IsWorktree bool    // linked worktree (shown as child, or top-level if its main isn't listed)
        MainPath   string  // for worktrees: main checkout path (first entry of worktree list)
        Status     Status
        Worktrees  []*Repo // linked worktrees of this repo, sorted Updated desc
        Expanded   bool    // UI fold state, default false
    }
    ```
  - `func QuickOrder(root string) []string`: direct child dirs of `root` that contain `.git` (dir or file). Sorted by the
    max mtime of {dir, `.git`, `.git/index`}, newest first. No git calls.
  - `func LoadRepo(path string) *Repo`: returns nil if `path` isn't a non-bare repo toplevel
    (`rev-parse --show-toplevel` != path after normPath). It fills Status, CommonDir, IsWorktree
    (`.git` is a file), and MainPath. If not a worktree, it fills Worktrees from `worktree list --porcelain`,
    skipping entry 0, `Bare` and `Prunable` entries, each loaded via ReadStatus and sorted Updated desc.
  - `func Dedupe(rs []*Repo) []*Repo`: drops top-level `IsWorktree` repos whose CommonDir equals some listed
    non-worktree repo's CommonDir. Keeps order.
  - `func SortRepos(rs []*Repo)`: stable sort by `Status.Updated` desc.

### Task 4: Actions

**Files:**
- Create: `actions.go`, `actions_test.go`

**Interfaces:**
- Consumes: `git` (Task 1); `Repo`, `Status` (Tasks 2–3); fixture helpers.
- Produces (each returns an error whose text is short and prefixed by the failing step):
  - `func BackToDefault(r *Repo, discard bool) error`: refuses with `"not allowed on a worktree"` when `r.IsWorktree`,
    and with `"unknown default branch"` when `r.Status.Default == ""`. If `discard`, it runs `reset --hard` then `clean -fd`.
    Then it runs `checkout <Default>` (error prefix `checkout: `) and `pull --ff-only` (prefix `pull: `). If the pull error
    mentions "Not possible to fast-forward" / "diverging", the text is `pull: not fast-forward`.
  - `func Pull(r *Repo) error`: refuses with `"no upstream"` or `"upstream gone"` without calling git. Otherwise it runs
    `pull --ff-only` (same `pull: ` rules).
  - `func Fetch(path string) error`: `fetch --all --prune`. Then, if `symbolic-ref refs/remotes/origin/HEAD` fails
    and an `origin` remote exists, it runs `remote set-head origin --auto` (an error there is ignored).
  - `func RemoveWorktree(wt *Repo, force bool) error`: `git -C wt.MainPath worktree remove [--force] wt.Path`.
    Never touches branches.
  - `func OpenEditor(path string) error`: `exec.LookPath("code")`. If missing, returns
    `VS Code 'code' command not found on PATH`. Otherwise it runs `exec.Command(bin, path).Start()` and does not wait.

### Task 5: Display rows (pure)

**Files:**
- Create: `rows.go`, `rows_test.go`

**Interfaces:**
- Consumes: `Repo`, `Status`.
- Produces:
  - `type row struct { Repo *Repo; Child bool }`
  - `func visibleRows(rs []*Repo, filter string) []row`: a repo row, then (if `Expanded`) its worktree rows.

    Matching worktrees show under it even when folded. When the repo itself matches and is folded, no children show.
  - `func stateText(s Status) string`: the STATE column text, as plain text without colors. Rules, joined by single spaces in this order:

  - `func relTime(now, t time.Time) string`: `<1m`→`now`, then `Nm`, `Nh`, `Nd`; zero time→`-`.

### Task 6: Bubble Tea UI

**Files:**
- Create: `ui.go`
- Modify: `go.mod`/`go.sum` (`go get github.com/charmbracelet/bubbletea github.com/charmbracelet/bubbles github.com/charmbracelet/lipgloss`)

**Interfaces:**
- Consumes: everything above.
- Produces:
  - `func newModel(root string) model` and `model` implements `tea.Model`.
  - `func (m model) Chosen() string`: the path picked with Enter, or `""`.

**Mechanics (decided here; the rest is the spec's Layout and Keys sections):**
- **Ordered pool:** `runPool(paths []string, fn func(string) tea.Msg, out chan<- tea.Msg)` starts 8 goroutines that
  read paths from one unbuffered channel, fed in slice order (FIFO, so newest-first holds). Results go to `out`.
  A `listen(out) tea.Cmd` re-arms after each message (standard Bubble Tea channel pattern).
- **Messages:** `repoLoadedMsg{*Repo}` (append, then `Dedupe` against existing rows), `loadDoneMsg{}` (then `SortRepos`
  and start the startup fetch over current repo paths in current order), `fetchedMsg{path string; err error}`
  (re-`LoadRepo` that path, preserve `Expanded`, keep the position until `r`), `actionDoneMsg{path string; err error}`.
  Header progress: `fetching… done/total`.
- **Cursor** is stored as a path, resolved to an index against `visibleRows` on each render.
- **Busy rows:** `map[string]bool`. STATE shows `…` while busy.
- **Confirm dialogs:** a queue `[]confirm{repo *Repo; kind (discard|removeWT); files []string}`. For `b` with a selection,
  build the queue from the dirty repos (in visible order). Clean repos run immediately; others wait for their answer.
  `y` runs that one with discard. `Esc` drops the whole queue **and** cancels the not-yet-started clean ones (so build
  the queue first, then start the clean ones only after the queue is answered or empty). Any other key skips it.
  The file list is truncated to 10 entries plus `+N more`. The remove-worktree dialog text:
  `Remove worktree <path>? Branch <branch> is kept.`, plus the file list and "these changes will be lost" if dirty.
- **Filter:** a `bubbles/textinput` is shown when `/` is pressed. Esc clears it, Enter keeps it and returns focus.
- **Selection:** `map[string]bool`, toggled by `x`. It is cleared after `b`/`p` dispatch.
- **Refusals** (`b` on a worktree, `d` on a repo, `p` without upstream) only set the status line.
- **`c`** calls `OpenEditor(row.Path)` and sets the status line to `opened <name> in VS Code`, or to the error text. It does not quit.
- **Enter** sets `chosen` to the row's Path and returns `tea.Quit`. `q`/`esc` (outside filter and dialog)/`ctrl+c`
  quit with `chosen = ""`.
- **View:** header, column header, rows (gutter: `✓` if selected, `▸`/`▾` if it has worktrees, `└` for child rows),
  divider, status line, footer keys. Colors per spec via lipgloss. Columns are sized to `tea.WindowSizeMsg` width,
  and the branch is truncated with `...`. Scroll so the cursor stays visible.
